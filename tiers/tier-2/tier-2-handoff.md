# Tier 2: Worker Report Handoff Record

This is the facilitator's official record for the report-based orchestration demo. It is not an initial worker prompt and should not contain prewritten follow-up prompts.

## Artifact flow

```text
orchestrator assignment packet
        │
        ├──► reports/tier-2/alpha-report.md
        ├──► reports/tier-2/beta-report.md
        └──► reports/tier-2/gamma-report.md  (blocked-state report, in parallel)
                         │
                         ▼
               orchestrator-review.md
                         │
                         ▼
              human review and live follow-up
```

## What the human does

1. Start a fresh Tier 2 round and give the orchestrator only the repository source material named in `tier-2-prompts.md`.
2. Copy the orchestrator's self-contained assignments into Alpha, Beta, and Gamma.
3. Allow all three workers to prepare their first reports in parallel. Gamma reports its blocked state; it does not wait silently.
4. Open each report with MarkView and review the evidence, scope, dependencies, and escalation items.
5. Copy each report's `Handoff Prompt to Orchestrator` back into the orchestrator.
6. Ask the orchestrator to read the supplied reports and create `reports/tier-2/orchestrator-review.md`.
7. Review that synthesis with the audience and decide which feedback, if any, should be sent to a worker.
8. Copy a follow-up prompt generated by the orchestrator only after the human chooses the target worker and desired outcome.

## Required report contents

Every worker report must identify:

- The assignment it received
- Its authority and forbidden scope
- Evidence actually inspected
- Proposed work, test plan, or blocked condition
- Dependencies and risks
- Contradictions requiring escalation
- Acceptance or release criteria
- A copy-ready `Handoff Prompt to Orchestrator`

## Orchestrator synthesis

The orchestrator's report should compare the workers rather than merely repeat them. It should identify:

- Agreements and independent corroboration
- Conflicting assumptions or ownership collisions
- Alpha/Beta dependency status
- Why Gamma remains blocked or what evidence would release it
- Human decisions required
- Proposed next actions

The human should be able to open this synthesis in MarkView and understand what happened without watching every terminal.

## Follow-up boundary

Follow-up prompts are deliberately generated during the session. They do not belong in `tier-2-prompts.md`, and this document must not turn them into a fixed script. The value of Tier 2 is that the next instruction is based on the reports and the human's judgment.

## Stop condition for the demonstration

Run one or two live feedback turns after the synthesis. Then stop and explain that a production workflow would continue until the human is satisfied with the evidence, ownership, dependency graph, and interrupt conditions before implementation begins.
